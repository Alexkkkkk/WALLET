# Windows-релизы WALLET

## Windows 10/11 x64: основной portable ZIP

Откройте [актуальный релиз](https://github.com/Alexkkkkk/WALLET/releases/latest) и выберите Windows ZIP для своей ОС и архитектуры. Для версии `v0.4.2` основной файл — [`WALLET-v0.4.2-windows10-11-x64.zip`](https://github.com/Alexkkkkk/WALLET/releases/download/v0.4.2/WALLET-v0.4.2-windows10-11-x64.zip), собранный с Python 3.12. Для проверки целостности используйте соседний файл [`WALLET-v0.4.2-windows10-11-x64.zip.sha256`](https://github.com/Alexkkkkk/WALLET/releases/download/v0.4.2/WALLET-v0.4.2-windows10-11-x64.zip.sha256). Распакуйте архив целиком и запустите `WALLET.exe`. Отдельная установка Python, pip или Berkeley DB для этого архива не требуется.

Если ZIP ещё не появился в Assets, дождитесь успешной сборки и публикации. Не заменяйте его ссылкой «Source code» или Python-пакетом: это другой способ установки, не готовое Windows-приложение.

Дополнительный артефакт с Python 3.11 сохраняется только в GitHub Actions как вариант для проверки совместимости. Он не прикладывается к релизу, не является Windows 7-сборкой и не заменяет основной ZIP. Официальная документация Python 3.11 и 3.12 указывает Windows 8.1 и новее; это минимальная ОС интерпретатора, а не обещание совместимости всей упаковки WALLET. Целевой профиль основного ZIP — Windows 10/11 x64. [1] [2]

Workflow `.github/workflows/build.yml` вызывает переиспользуемый `.github/workflows/windows-exe.yml`, который также допускает ручной запуск. Оба варианта, с Python 3.11 и 3.12, собираются на `windows-2022` — GitHub-hosted Windows Server 2022. Подготовленное окружение обеспечивает нативную Berkeley DB и Python-зависимости, которые включаются в EXE вместе с Python и Tcl/Tk.

Скрипт `scripts/verify_windows_bundle.py` запускает standalone EXE вне каталога исходников и без Conda в PATH. Он проверяет версию, `--selftest`, офлайн AI при строгой кодировке `cp1252`, чтение синтетического BDB-кошелька и восстановление известного пароля с двумя процессами, неизменность входного кошелька и появление видимого GUI при запуске без аргументов. Успех этих проверок подтверждает работоспособность на Windows Server 2022. Он не заменяет испытание на реальной Windows 10, пользовательском кошельке или Windows 7. Открытие окна само по себе также не доказывает, что нативный драйвер читает BDB и подбор работает.

Релиз публикует один job в `build.yml` после успешных обеих Windows-сборок и сборки/проверки Python-пакетов. Тег должен совпадать с версией пакета. В релиз включаются только основной Python 3.12 Windows ZIP, его SHA-256 и Python-пакеты; `scripts/release_notes.py` формирует явные инструкции выбора ОС.

## Windows 7 SP1 x64: проверенного готового EXE нет

Ни один старый релиз или современный ZIP WALLET нельзя считать Windows 7-совместимым без отдельного испытания на этой ОС. В частности, `v0.4.0` и `v0.4.1` содержали Python-пакеты версии `0.3.0` и неполную EXE-упаковку. Имя тега не подтверждает версию содержимого или совместимость с Windows 7; эти выпуски не следует использовать как Windows 7-релизы.

Для экспериментальной legacy-сборки нужен официальный **Python 3.8.10 x64 с Tcl/Tk**. Документация Python 3.11/3.12 рекомендует ветку 3.8 для Windows 7. В 3.8.10 ещё есть официальный 64-битный Windows installer; последующие релизы 3.8 выпускались только как исходники. Это последний официальный выпуск этой ветки с бинарными установщиками, а не актуальная безопасная версия Python. [1] [2] [3] [4]

Одного Python недостаточно. Необходимо закрепить и проверить весь набор зависимостей, включая нативные DLL и инструменты упаковки, именно для Windows 7 SP1 x64. В проекте для Windows/Python 3.8 уже указан `cryptography==42.0.7`, а драйвером BDB служит `bsddb3`; эти маркеры не являются полностью проверенным legacy-набором. Нужны совместимая 64-битная Berkeley DB и сборка её Python-драйвера. Произвольные DLL из непроверенных источников использовать нельзя.

Отдельного Windows 7 workflow проект не предоставляет. Готовую legacy-упаковку можно объявить Windows 7-совместимой только после испытания на отдельной машине или VM с Windows 7 SP1 x64: запуск без установленного Python, открытие GUI, `--selftest`, офлайн AI smoke-test и сквозное чтение/подбор на синтетическом BDB-кошельке. Проверка грамматики Python 3.8, успешная современная Actions-сборка или её ручной запуск не заменяют эти испытания.

Python 3.8 прекратил получать обновления 7 октября 2024 года. Legacy-профиль экспериментальный; для работы с реальными средствами предпочтительна поддерживаемая ОС. [4]

## Python-пакеты и исходники — не portable-приложение

Файлы `wallet_recover_local-0.4.2-py3-none-any.whl` и `wallet_recover_local-0.4.2.tar.gz` предназначены для установки в Python-окружение. Они требуют отдельного интерпретатора и зависимостей. `py3-none-any` описывает сам wheel, но не означает, что его нативные зависимости или приложение совместимы со всеми ОС, включая Windows 7.

Автоматические GitHub-ссылки «Source code (zip)» и «Source code (tar.gz)» содержат исходники репозитория. Они не содержат готовый standalone `WALLET.exe`. Для обычного запуска на Windows 10/11 x64 выбирайте именно основной Windows ZIP из Assets.
