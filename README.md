# WALLET — локальное восстановление пароля wallet.dat

CLI-утилита на Python для проверки **ваших кандидатов пароля к вашему кошельку** Bitcoin Core legacy (Berkeley DB, метод деривации 0). Во время работы нет сетевых запросов, телеметрии и отправки файлов. Репозиторий не содержит настоящих кошельков, паролей или ключей.

**Статус:** начальная реализация. Юнит-тесты и сквозной тест используют синтетические записи и временный BDB-файл. Совместимость с реальным кошельком пользователя пока не проверена. Программа не гарантирует восстановление пароля и не предназначена для хранения средств.

## Возможности

- Чтение закрытой резервной копии BDB-кошелька: дополнительная временная копия с правами 0600 открывается через `DB_RDONLY`, logical database `main`; исходник не открывается для записи.
- Разбор CompactSize, нескольких `mkey`, `ckey` с опциональной контрольной суммой.
- SHA-512 KDF и AES-256-CBC с PKCS#7, как в Bitcoin Core method 0.
- Обязательное подтверждение кандидата: расшифровать 32-байтный секрет и сравнить вычисленный secp256k1-публичный ключ с записью `ckey` (сжатые и несжатые ключи).
- Несколько процессов, счётчик полученных завершённых результатов, самопроверка.
- Без `ckey` подбор прекращается: один паддинг не считается доказательством пароля.

## Установка (Linux, Python 3.10+)

```bash
git clone https://github.com/Alexkkkkk/WALLET.git
cd WALLET
sudo apt-get update
sudo apt-get install -y libdb-dev python3-dev python3-venv build-essential
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m wallet_recover --selftest
```

Зависимости: `pycryptodome` (AES), `cryptography` (secp256k1), `bsddb3` (BDB). Установка пакетов требует интернета; сама утилита работает офлайн. Windows/macOS не тестировались, для Windows проще использовать WSL.

## Использование

**Сначала закройте Bitcoin Core**, затем сделайте отдельную резервную копию. Не копируйте активно изменяемую базу. Фактический путь зависит от вашей установки и имени кошелька.

```bash
cp /путь/к/wallet.dat /безопасный/путь/wallet-backup.dat

# Только посмотреть параметры, без подбора:
python -m wallet_recover --wallet /безопасный/путь/wallet-backup.dat --print-mkey

# Проверить ваши кандидаты:
python -m wallet_recover \
  --wallet /безопасный/путь/wallet-backup.dat \
  --wordlist /безопасный/путь/words.txt \
  --jobs 4 \
  --save /безопасный/путь/found_password.bin
```

Также поддерживается `python wallet_recover.py ...`. Пример словаря находится в `examples/words.example.txt`; замените его собственными воспоминаниями, а не используйте как рекомендацию паролей.

### Словарь и результат

- Одна строка = один кандидат; снимается только LF или CRLF. Пробелы сохраняются, пустая строка проверяет пустой пароль.
- Читаются точные байты без Unicode-нормализации. Для обычных текстовых паролей используйте UTF-8 без BOM. Пароли с переводом строки данным форматом не представляются.
- При `--save` пароль **не печатается**, сохраняются точные байты без добавленного перевода строки. Выходной файл создаётся эксклюзивно с режимом 0600 на POSIX; существующий файл не перезаписывается. В других ОС проверьте ACL отдельно.
- Без `--save` пароль выводится в терминал как bytes и hex — учитывайте историю/логи терминала.
- Код возврата: `0` — подтверждённый пароль / успешная диагностика; `1` — кандидаты закончились; `2` — ошибка; `130` — прерывание.
- Счётчик отражает полученные завершённые результаты, а не задачи в очереди. При остановке часть уже выполненных/выполняющихся задач может не попасть в счётчик. Это не глобальный номер кандидата в словаре.

## Исправления исходного наброска

1. KDF: `h = SHA512(password || salt)`, затем `nRounds - 1` раз **`h = SHA512(h)`**. Добавлять пароль и соль в каждый раунд нельзя. Первые 32 байта — ключ, следующие 16 — IV. `openssl enc -iter` использует PBKDF2 и не является эталоном этой KDF.
2. Ключ записи `mkey` — сериализованная строка `mkey` + uint32 ID, не буквальный `b'mkey'`. Ключ `ckey` — сериализованные тип и публичный ключ. Значение `ckey` содержит сериализованный вектор ciphertext, в новых записях также checksum.
3. Расшифрованный секрет `ckey` имеет **32 байта**, не 33; флаг сжатия берётся из формата публичного ключа. IV — первые 16 байт SHA256d(pubkey).
4. Простого попадания приватного скаляра в диапазон недостаточно: публичный ключ вычисляется и сравнивается всегда. Опции отключения этой проверки нет.
5. Кошелёк читается из временной копии без создания BDB environment рядом с исходником. Все mkey обрабатываются, неизвестные методы отвергаются.

Сверено с Bitcoin Core v27.0:
- [crypter.cpp: KDF, DecryptKey](https://github.com/bitcoin/bitcoin/blob/v27.0/src/wallet/crypter.cpp)
- [walletdb.cpp: mkey, ckey и checksum](https://github.com/bitcoin/bitcoin/blob/v27.0/src/wallet/walletdb.cpp)
- [bdb.cpp: logical database main](https://github.com/bitcoin/bitcoin/blob/v27.0/src/wallet/bdb.cpp)

## Тесты

```bash
pip install -e '.[test]'
python -m pytest -q
python -m wallet_recover --selftest
```

Проверяются: KDF против `EVP_BytesToKey` из системной OpenSSL (тест пропускается, если libcrypto отсутствует); паддинг; сериализация и повреждённые записи; checksum; сжатые/несжатые публичные ключи; несколько mkey; отрицательные пароли; BDB `main`; CLI с двумя процессами; отсутствие изменений исходника; безопасное сохранение. Ключи фикстур общедоступны и **не должны получать средства**. На реальном пользовательском wallet.dat тесты не проводились.

## Ограничения и безопасность

- Только legacy BDB и method 0 с пустыми дополнительными параметрами. SQLite/descriptor-кошельки, seed-фразы, аппаратные кошельки и другие KDF не поддерживаются. Форки отдельно не тестировались: совпадение имени `wallet.dat` не означает совместимость.
- Отсутствие `mkey` не доказывает отсутствие пароля: это может быть неподдерживаемый/неполный файл. Отсутствие `ckey` не позволяет подтвердить пароль этим инструментом.
- Проверяется только заданный словарь; случайный длинный пароль практически не восстановить. Скорость зависит от CPU, количества раундов и числа процессов; обещаний p/s или ускорения нет. Это CPU-инструмент, без GPU, правил и checkpoints.
- При ошибке Berkeley DB проверьте целостность копии и совместимость версии библиотеки. Не делайте upgrade/repair оригинала и не считайте любую ошибку BDB несовместимостью версий. Временная копия не заменяет корректную резервную копию закрытого кошелька.
- Секреты находятся в памяти процессов. Python не гарантирует их безопасное обнуление, удаление временного файла не гарантирует физическое стирание. Используйте доверенный компьютер и защищённое локальное хранилище; учитывайте swap и резервные копии.
- `.gitignore` исключает типичные кошельки, словари и файлы результата, но это не защита от произвольного имени или `git add -f`. Никогда не загружайте реальные wallet.dat, словари, пароли, хэши кошелька или токены в публичный репозиторий.
- Используйте только для своего кошелька либо с явным разрешением владельца.
