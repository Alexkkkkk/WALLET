# WALLET — локальное восстановление пароля wallet.dat

Локальная утилита на Python с CLI и русским оконным интерфейсом Tkinter для восстановления **своего пароля** к legacy-кошельку Bitcoin Core (Berkeley DB, метод деривации 0). Основной поиск не использует сеть. Дополнительный AI-генератор работает офлайн по умолчанию; Ollama остаётся на localhost. Внешний OpenAI-провайдер доступен только при явном выборе. Репозиторий не содержит настоящих кошельков, паролей или ключей.

**Статус:** начальная реализация. Юнит-тесты и сквозной тест используют синтетические записи и временный BDB-файл. Совместимость с реальным кошельком пользователя пока не проверена. Программа не гарантирует восстановление пароля и не предназначена для хранения средств.

## Возможности

- Оконный интерфейс: выбор копии кошелька и словаря, диагностика, число процессов, запуск/остановка, счётчик и скорость, журнал без паролей, сохранение результата только по отдельной команде.

- Чтение закрытой резервной копии BDB-кошелька: дополнительная временная копия с правами 0600 открывается через `DB_RDONLY`, logical database `main`; исходник не открывается для записи.
- Разбор CompactSize, нескольких `mkey`, `ckey` с опциональной контрольной суммой.
- SHA-512 KDF и AES-256-CBC с PKCS#7, как в Bitcoin Core method 0.
- Обязательное подтверждение кандидата: расшифровать 32-байтный секрет и сравнить вычисленный secp256k1-публичный ключ с записью `ckey` (сжатые и несжатые ключи).
- Несколько процессов, счётчик полученных завершённых результатов, самопроверка.
- Без `ckey` подбор прекращается: один паддинг не считается доказательством пароля.
- AI-слои: реконструкция из воспоминаний, русско-латинская транслитерация, исправление раскладки, правила регистра/символов/лет/l33t, ранжирование и экспериментальный символьный Transformer.
- Необязательный локальный Hashcat-адаптер для уже извлечённого пользователем Bitcoin wallet hash (mode 11300); без Colab и автоматической загрузки файлов.

## Быстрый запуск одной командой

```bash
git clone https://github.com/Alexkkkkk/WALLET.git
cd WALLET
./scripts/bootstrap.sh
```

Скрипт ставит системные библиотеки (`libdb-dev`, `python3-tk`, `xvfb`), создаёт `.venv`, устанавливает пакет с extras `[ai,test]`, затем сам прогоняет `--selftest` и весь набор тестов. Ожидаемый результат в конце — `Self-test passed` и `passed` без `failed`.

Проверено в чистом Linux-контейнере (Ubuntu 24.04, Python 3.12): `42 passed`, GUI-тесты `12 passed, 1 skipped`, сквозной подбор пароля на синтетическом BDB-кошельке с сохранением в файл `0600`. Без `libdb-dev` драйвер `berkeleydb` не собирается — это главная причина «не работает» на чистой системе; без `python3-tk` не открывается окно.

Непрерывная интеграция (`.github/workflows/build.yml`) прогоняет те же проверки на Python 3.10/3.11/3.12, включая проверку грамматики под Python 3.8.

## Совместимость зависимостей

`berkeleydb` — нативное расширение, собираемое из исходников, готовых wheel на PyPI нет. Версия 18.1.16+ не собирается на CPython 3.10, поэтому в `requirements.txt` и `pyproject.toml` стоит маркер: `berkeleydb>=18.1,<18.1.16` для Python 3.10 и `berkeleydb>=18.1` для 3.11+. Сборка требует `libdb-dev`, `libdb++-dev` и компилятора — их ставит `scripts/bootstrap.sh` и CI.

Для GUI на Ubuntu дополнительно нужны `python3-tk`; для безэкранных GUI-тестов — `xvfb`.

## Оконный интерфейс и Windows 7 / 10

Запуск из каталога проекта после установки зависимостей:

```bat
python -m wallet_recover.gui
```

На Windows также есть `start_gui.bat`: он использует `.venv\Scripts\python.exe`, если окружение существует, иначе `python` из PATH. Скрипт не устанавливает пакеты и не скачивает программы. После `pip install .` доступна команда `wallet-recover-gui`.

1. Закройте Bitcoin Core и сделайте отдельную резервную копию.
2. Выберите копию `wallet.dat` и нажмите «Проверить кошелёк».
3. Выберите словарь с вашими кандидатами: одна строка = один пароль, без изменения пробелов и кодировки.
4. Подтвердите разрешение владельца, задайте число процессов и начните проверку. «Остановить» завершает фоновые процессы; сохранения позиции и возобновления пока нет.
5. При успехе нажмите «Сохранить пароль…». Файл содержит незашифрованные точные байты, без перевода строки. Существующие файлы не перезаписываются. На Windows отдельно проверьте права NTFS: режим POSIX 0600 не заменяет ACL.

### Статус совместимости — без гарантии запуска

| Цель | Подготовка | Что ещё требуется |
| --- | --- | --- |
| Windows 10 | Python 3.11 с Tcl/Tk; стандартное окружение и зависимости | Нативный драйвер Berkeley DB и проверка на Windows |
| Windows 7 SP1 | Экспериментально: Python 3.8.10 с Tcl/Tk; для Python 3.8 на Windows закреплён `cryptography==42.0.7` | Совместимый нативный драйвер Berkeley DB и проверка именно на Windows 7 |

В этой среде **нет Windows**. Проверены Linux/Python 3.12, GUI через Xvfb, синтетические BDB-кошельки и синтаксис модулей по грамматике Python 3.8. Проверка синтаксиса не является тестом исполнения на Python 3.8 или Windows. Готового и проверенного `.exe` пока нет.

**Нерешённый блокер упаковки:** проверка PyPI не обнаружила Windows wheels для `bsddb3`/`berkeleydb` под целевые CPython 3.8 и 3.11 x64. Поэтому `pip install -r requirements.txt` на чистой Windows может остановиться на сборке BDB; одной установки Python недостаточно. Нужна собственная сборка драйвера с совместимой нативной Berkeley DB и компилятором соответствующей архитектуры, либо проверенный бинарный пакет из доверенного источника. Проект не скачивает случайные DLL. Ошибка драйвера показывается в журнале; открытие самого окна драйвера не требует. WSL не является решением для Windows 7.

Python 3.8 уже не получает исправлений безопасности. Старый `cryptography` выбран только как экспериментальная совместимая ветка, а не как безопасная актуальная рекомендация. Для реальных средств предпочтительна поддерживаемая ОС. Источники: [Python 3.8.10](https://www.python.org/downloads/release/python-3810/), [changelog cryptography, 42.0.7](https://cryptography.io/en/latest/changelog/).

## Использование

**Сначала закройте Bitcoin Core**, затем сделайте отдельную резервную копию. Не копируйте активно изменяемую базу. Фактический путь зависит от вашей установки и имени кошелька.

```bash
cp /путь/к/wallet.dat /безопасный/путь/wallet-backup.dat

# Только посмотреть параметры, без подбора:
python -m wallet_recover --wallet /безопасный/путь/wallet-backup.dat --print-mkey

# Проверить ваши кандидаты:
python -m wallet_recover \
  --wallet /безопасный/путь/wallet-backup.dat \
  --wordlist /безопасный/путь/words.txt \
  --jobs 4 \
  --save /безопасный/путь/found_password.bin
```

Также поддерживается `python wallet_recover.py ...`. Пример словаря находится в `examples/words.example.txt`; замените его собственными воспоминаниями, а не используйте как рекомендацию паролей.

### AI-генерация словаря из воспоминаний

Офлайн-реконструктор превращает короткие воспоминания и известные фрагменты в ограниченный список вариантов, добавляя транслитерацию, типичные суффиксы и варианты раскладки. Файл создаётся эксклюзивно с правами 0600; существующие файлы не перезаписываются.

```bash
python -m wallet_recover \
  --ai-generate /безопасный/путь/ai-candidates.txt \
  --memory "помню имя кота Барсик, год 2019 и восклицательный знак" \
  --ai-provider offline \
  --ai-limit 5000

# Затем проверить сгенерированный список обычным локальным движком:
python -m wallet_recover \
  --wallet /безопасный/путь/wallet-backup.dat \
  --wordlist /безопасный/путь/ai-candidates.txt \
  --jobs 4 --save /безопасный/путь/recovered.bin
```

Для локальной языковой модели можно явно выбрать Ollama (установите Ollama отдельно и скачайте модель самостоятельно):

```bash
ollama pull mistral
python -m wallet_recover --ai-generate /безопасный/путь/ai-candidates.txt \
  --memory "ваши личные воспоминания о пароле" --ai-provider ollama --ai-model mistral
```

Ollama вызывается только по локальному адресу `127.0.0.1:11434`. Для OpenAI есть отдельный выбор `--ai-provider openai --ai-model gpt-5-mini`; при нём текст ваших воспоминаний передаётся внешнему провайдеру, поэтому не включайте секретные данные, если это нежелательно. По умолчанию провайдер — `offline`, сетевой AI не вызывается. `--ai-no-neural` отключает экспериментальную генерацию символьной модели, `--ai-no-rank` — ранжирование.

### Необязательный локальный Hashcat

Вложенный сценарий Colab намеренно заменён локальным вариантом: `wallet.dat`, извлечённый wallet hash, словарь, пароль и Hashcat potfile могут раскрыть доступ к средствам. Не загружайте их в Colab, Google Drive, веб-генераторы или публичный репозиторий. Hashcat и доверенный `bitcoin2john.py` нужно установить отдельно из официально проверенного источника; извлекать hash следует только из резервной копии и локально. Программа не скачивает extractor, не извлекает hash автоматически и не делает сетевых запросов.

```bash
# Установите Hashcat и локально получите wallet.hash доверенным extractor.
# Запуск для своего кошелька (Bitcoin/Litecoin wallet.dat, Hashcat mode 11300):
python -m wallet_recover \
  --hashcat-hash /безопасный/путь/wallet.hash \
  --hashcat-wordlist /безопасный/путь/ai-candidates.txt \
  --hashcat-state-dir /безопасный/путь/hashcat-state \
  --i-own-wallet
```

Hashcat запускается без shell, с `-m 11300 -a 0`; состояние и potfile остаются в локальном каталоге с ограниченными правами. Potfile Hashcat содержит пароль в открытом виде — храните его как секрет. Для продолжения прерванной сессии передайте те же файлы и путь состояния, добавив `--hashcat-resume`. Не запускали Hashcat на реальных кошельках в тестах; доступность режима зависит от сборки и GPU-драйвера. Это отдельный бэкенд: встроенная проверка Python по-прежнему подтверждает пароль через публичный ключ.

### Словарь и результат

- Одна строка = один кандидат; снимается только LF или CRLF. Пробелы сохраняются, пустая строка проверяет пустой пароль.
- Читаются точные байты без Unicode-нормализации. Для обычных текстовых паролей используйте UTF-8 без BOM. Пароли с переводом строки данным форматом не представляются.
- При `--save` пароль **не печатается**, сохраняются точные байты без добавленного перевода строки. Выходной файл создаётся эксклюзивно с режимом 0600 на POSIX; существующий файл не перезаписывается. В других ОС проверьте ACL отдельно.
- Без `--save` пароль выводится в терминал как bytes и hex — учитывайте историю/логи терминала.
- Код возврата: `0` — подтверждённый пароль / успешная диагностика; `1` — кандидаты закончились; `2` — ошибка; `130` — прерывание.
- Счётчик отражает полученные завершённые результаты, а не задачи в очереди. При остановке часть уже выполненных/выполняющихся задач может не попасть в счётчик. Это не глобальный номер кандидата в словаре.

## Исправления исходного наброска

1. KDF: `h = SHA512(password || salt)`, затем `nRounds - 1` раз **`h = SHA512(h)`**. Добавлять пароль и соль в каждый раунд нельзя. Первые 32 байта — ключ, следующие 16 — IV. `openssl enc -iter` использует PBKDF2 и не является эталоном этой KDF.
2. Ключ записи `mkey` — сериализованная строка `mkey` + uint32 ID, не буквальный `b'mkey'`. Ключ `ckey` — сериализованные тип и публичный ключ. Значение `ckey` содержит сериализованный вектор ciphertext, в новых записях также checksum.
3. Расшифрованный секрет `ckey` имеет **32 байта**, не 33; флаг сжатия берётся из формата публичного ключа. IV — первые 16 байт SHA256d(pubkey).
4. Простого попадания приватного скаляра в диапазон недостаточно: публичный ключ вычисляется и сравнивается всегда. Опции отключения этой проверки нет.
5. Кошелёк читается из временной копии без создания BDB environment рядом с исходником. Все mkey обрабатываются, неизвестные методы отвергаются.

Сверено с Bitcoin Core v27.0:
- [crypter.cpp: KDF, DecryptKey](https://github.com/bitcoin/bitcoin/blob/v27.0/src/wallet/crypter.cpp)
- [walletdb.cpp: mkey, ckey и checksum](https://github.com/bitcoin/bitcoin/blob/v27.0/src/wallet/walletdb.cpp)
- [bdb.cpp: logical database main](https://github.com/bitcoin/bitcoin/blob/v27.0/src/wallet/bdb.cpp)

## Тесты

```bash
pip install -e '.[test]'
python -m pytest -q
python -m wallet_recover --selftest
```

Проверяются: KDF против `EVP_BytesToKey` из системной OpenSSL (тест пропускается, если libcrypto отсутствует); паддинг; сериализация и повреждённые записи; checksum; сжатые/несжатые публичные ключи; несколько mkey; отрицательные пароли; BDB `main`; CLI с двумя процессами; отсутствие изменений исходника; безопасное сохранение. Ключи фикстур общедоступны и **не должны получать средства**. На реальном пользовательском wallet.dat тесты не проводились.

## Ограничения и безопасность

- Только legacy BDB и method 0 с пустыми дополнительными параметрами. SQLite/descriptor-кошельки, seed-фразы, аппаратные кошельки и другие KDF не поддерживаются. Форки отдельно не тестировались: совпадение имени `wallet.dat` не означает совместимость.
- Отсутствие `mkey` не доказывает отсутствие пароля: это может быть неподдерживаемый/неполный файл. Отсутствие `ckey` не позволяет подтвердить пароль этим инструментом.
- Проверяется только заданный словарь; случайный длинный пароль практически не восстановить. Встроенная проверка Python использует CPU; локальный Hashcat доступен отдельно и требует самостоятельной установки. Нейросимвольный Transformer — экспериментальный код без предобученных весов, не обещает полезного восстановления; качество семантической реконструкции зависит от Ollama/модели либо офлайн-эвристик.
- При ошибке Berkeley DB проверьте целостность копии и совместимость версии библиотеки. Не делайте upgrade/repair оригинала и не считайте любую ошибку BDB несовместимостью версий. Временная копия не заменяет корректную резервную копию закрытого кошелька.
- Секреты находятся в памяти процессов. Python не гарантирует их безопасное обнуление, удаление временного файла не гарантирует физическое стирание. Используйте доверенный компьютер и защищённое локальное хранилище; учитывайте swap и резервные копии.
- `.gitignore` исключает типичные кошельки, словари и файлы результата, но это не защита от произвольного имени или `git add -f`. Никогда не загружайте реальные wallet.dat, словари, пароли, хэши кошелька или токены в публичный репозиторий.
- Используйте только для своего кошелька либо с явным разрешением владельца.
